# Система управления пользователями с разграничением прав доступа

## Архитектура системы прав доступа

### Ролевая модель (RBAC - Role-Based Access Control)

Система использует ролевую модель доступа, где:
- **Пользователям** назначаются **роли**
- **Ролям** назначаются **разрешения**
- **Разрешения** определяют доступ к конкретным ресурсам и действиям

### Таблицы базы данных

1. **users** - Пользователи
   - id, email, пароль, личные данные, статусы
   - is_active - флаг активности (мягкое удаление)

2. **roles** - Роли
   - id, название, описание
   - is_system - системные роли (нельзя удалять)

3. **permissions** - Разрешения
   - id, название, описание, ресурс, действие

4. **user_role** - Связь пользователей и ролей (многие-ко-многим)

5. **role_permission** - Связь ролей и разрешений (многие-ко-многим)

6. **token_blacklist** - Черный список JWT токенов

### Стандартные роли и разрешения

#### Роли:
1. **admin** - Администратор системы
   - Все разрешения
   - Управление пользователями, ролями, разрешениями

2. **user** - Обычный пользователь
   - Базовые разрешения на чтение своего профиля

#### Разрешения (ресурс:действие):
- `users:read` - Просмотр пользователей
- `users:write` - Редактирование пользователей
- `users:delete` - Удаление пользователей
- `roles:manage` - Управление ролями
- `permissions:manage` - Управление разрешениями

### Правила доступа

1. **401 Unauthorized** - если не удается определить пользователя
2. **403 Forbidden** - если пользователь определен, но не имеет нужных прав
3. **Мягкое удаление** - пользователь деактивируется (is_active=False)
4. **JWT токены** - для аутентификации с черным списком при выходе

### API Endpoints

#### Аутентификация
- POST `/auth/register` - Регистрация
- POST `/auth/login` - Вход в систему
- POST `/auth/logout` - Выход из системы
- POST `/auth/refresh-token` - Обновление токена

#### Пользователи
- GET `/users/me` - Получить свой профиль
- PUT `/users/me` - Обновить свой профиль
- DELETE `/users/me` - Удалить свой аккаунт
- GET `/users/{id}` - Получить пользователя (требуются права)
- GET `/users/` - Список пользователей (требуются права)

#### Администрирование
- CRUD для ролей: `/admin/roles/*`
- CRUD для разрешений: `/admin/permissions/*`
- Управление ролями пользователей: `/admin/users/{id}/roles`
